# מ־0 ל־100 · RAMON SAFETY DAY 2026

אפליקציית Web אינטראקטיבית לפעילות המרכזית ביום הבטיחות התעופתי של מגדל הפיקוח אילת רמון.

כ־20 פקחים עוברים יחד את אותו תרחיש תנועה בן ששה שלבים. לאורך הדרך נמדד — באופן אנונימי —
כיצד כל אחד מהם חווה את התפתחות העומס. בסיום, הקבוצה רואה בעיניים שלה שהעלייה מ־0 ל־100
לא קרתה אצל כולם באותה נקודה ולא באותו קצב.

---

## אפליקציה אחת, deployment אחד

הכול רץ כ־Worker יחיד ב־Cloudflare: אותה כתובת, אותו deployment, ו־routes פנימיים.

| מסך | נתיב | מיועד ל |
|---|---|---|
| משתתף | `/` | **הקישור הראשי.** הטלפון של כל פקח (Mobile-first) |
| מנחה | `/admin` | המחשב, הטאבלט או הטלפון שלך — נכנסים אליו עם קוד המנחה |
| הקרנה | `/live` | המסך שמשותף ב־Zoom (16:9) |
| דוח | `/report` | נפתח מתוך מסך המנחה |

הקישור הראשי מוביל למסך הכניסה, ובו **שני מסלולים נפרדים**:

| מסלול | כפתור | קוד |
|---|---|---|
| משתתף | **כניסה לפעילות** (ראשי) | `1111` |
| מנחה | **כניסת מנחה** (משני) | `ADMIN_KEY`, ברירת מחדל `0000` |

כל מסלול מקבל אך ורק את הקוד שלו: קוד הפעילות אינו פותח את מסך הניהול,
ומפתח המנחה אינו מצרף לפעילות. הבדיקה נעשית **בשרת בלבד** — הלקוח מקבל
אסימון אטום, המפתח עצמו לעולם אינו מגיע לדפדפן, ואינו מוצג בשום מקום.

מתוך ה־Admin יש כפתור **🖥 מסך הקרנה** שפותח את `/live` בטאב חדש לשיתוף
ב־Zoom — אותה אפליקציה, אותו Session.

כל עוד הלובי פתוח, משתתף יכול ללחוץ **יציאה מהפעילות** ולפנות את מקומו —
שימושי אם נכנסת בטעות כמשתתף לפני שנכנסת כמנחה. אחרי תחילת הפעילות
האפשרות נעלמת, כדי שאיש לא ינעל את עצמו בחוץ.

קוד הכניסה לפעילות הוא **`1111`** קבוע, ומוצג במסך המנחה וגם בגדול על מסך
ההקרנה, כך שמשתתפים בחדר וב־Zoom רואים אותו יחד. הוא מוגדר ב־`JOIN_CODE`
בקובץ [`shared/scenario.js`](shared/scenario.js).

## פריסה

האפליקציה פרוסה בכתובת:

**https://ramon-zero-to-hundred.alon3005nissani.workers.dev**

לפריסה מחדש:

```bash
npx wrangler login                              # פעם אחת
npx wrangler secret put ADMIN_KEY               # מפתח הכניסה למסך המנחה
npm run deploy                                  # בונה ופורס
```

`ADMIN_KEY` הוא ה־secret היחיד, וברירת המחדל היא `0000`.

**שים לב:** `0000` הוא מפתח קצר וצפוי, והאפליקציה פתוחה לכל מי שמגיע לכתובת.
מי שינחש אותו יכול להתחיל, לאפס או לסיים את הפעילות ולראות את התוצאות.
זה מקובל לפעילות חד־פעמית של רבע שעה בכתובת שלא פורסמה, אבל אם תרצה
להשאיר את האפליקציה באוויר אחרי יום הבטיחות — כדאי להחליף:

```bash
npx wrangler secret put ADMIN_KEY
```

## ארכיטקטורה

```
Cloudflare Worker
├─ Static Assets (dist/)        הממשק. כל נתיב שאינו קובץ מוגש כ־index.html,
│                               כך ש-/admin, /live ו-/report הם routes פנימיים
└─ Durable Object "SessionRoom" מופע יחיד שמחזיק את מצב הפעילות ואת כל
                                חיבורי ה־WebSocket
```

רק `/ws` ו־`/api/*` מגיעים ל־Durable Object; כל השאר מוגש כנכס סטטי.
ה־DO מחזיק את המצב בזיכרון ומשקף אותו ל־storage שלו, כך שהוא שורד הפעלה
מחדש באמצע פעילות. החיבורים הם WebSocket רגילים (ללא hibernation), כך
שה־DO נשאר חי לאורך הפעילות וההשהיות הקצרות בתרחיש פועלות כמתוכנן.

## מהלך הפעילות (כ־15 דקות)

1. פותחים את `/live` ומשתפים אותו ב־Zoom, ואת `/admin` על המסך הפרטי שלך.
2. המשתתפים נכנסים ל־`/` ומקלידים את קוד הפעילות.
3. **התחל פעילות** — הלובי ננעל. מרגע זה לא ניתן להצטרף.
4. הכפתור הגדול במסך המנחה מפעיל התפתחות אחת בכל לחיצה. מעליו תמיד מוצג
   מה קורה **עכשיו**, מה **הבא**, והערת תזמון **למנחה בלבד**.
5. כשנפתחת מדידת עומס, הכפתור הגדול הופך ל־**סגור הצבעה**. לאחר הסגירה:
   **המשך ללא חשיפה** (ברירת המחדל) או **👁 חשוף תוצאות**.
6. בסוף התרחיש: שאלת נקודת השינוי → חשיפה → גרף מסלולי העומס (4 שלבים) →
   שאלה פתוחה → קיר תשובות → מסך סיום.

## שלושה מופעים של אותה חוויה

אותו state ואותם רכיבים מוצגים בשלושה מקומות, ונבדלים רק בפריסה:

```
טלפון המשתתף  ←→  מסך ההקרנה  ←→  "תצוגת משתתף בזמן אמת" בתוך ה־Admin
```

התצוגה ב־Admin אינה הדמיה ואינה צילום: היא מריצה את אותו רכיב `ParticipantStage`
שרץ בטלפונים, על תצוגת משתתף שמגיעה מהשרת. לכן לא ייתכן מצב שבו המנחה רואה
משהו שונה ממה שהמשתתפים רואים.

**כל התפתחות מוצגת בכרטיס הגדול.** בראש לוח התנועה יושב כרטיס
**התפתחות אחרונה** שמציג את ההתפתחות שהופעלה זה עתה — למשל
`AIZ801 · READY FOR TAXI`. כל התפתחות מחליפה את הקודמת; הוא אינו נצבר.
אירועים בעלי תצוגה ייעודית (השיחה הנכנסת, הקורמורנים, MAYDAY) מחליפים אותו
בכרטיס שלהם. במקביל הסטריפ עצמו ממשיך לקבל את אנימציית ההדגשה.

**חשיפות מגיעות גם לטלפונים.** כשהמנחה לוחץ "חשוף תוצאות", אותה חשיפה מופיעה
בו־זמנית על מסך ההקרנה ובמכשיר האישי של כל משתתף — התפלגות, ציר נקודת השינוי,
גרף מסלולי העומס, ממוצע הקבוצה, מסרי הסיכום וקיר התשובות. לפני החשיפה הנתונים
כלל אינם נשלחים למכשיר.

## עקרונות שנאכפים במערכת

- **אנונימיות** — אין שם, מספר עובד או מזהה אישי. כל משתתף מקבל מזהה אקראי אטום
  בלבד, שנועד לחבר את מדידות העומס שלו לכדי מסלול אחד. גם ב־Admin וגם בדוח אי אפשר
  לדעת מי אמר מה.
- **תשובה שנשלחה נעולה** — נאכף בשרת, לא רק ב־UI.
- **רק המנחה סוגר שאלה**, ורק הוא מחליט אם לחשוף. שום תוצאה אינה נחשפת אוטומטית.
- **אין הצטרפות לאחר תחילת הפעילות** — אבל משתתף קיים שאיבד רשת, סגר דפדפן או
  ביצע Refresh חוזר אוטומטית לשלב הנוכחי עם התשובות ששלח.
- **המסך המשותף לעולם אינו מציג כלי Admin**, ובזמן הצבעה הוא מציג מונה משיבים בלבד —
  לא התפלגות ולא ממוצע.
- **החירום אינו מוחק את התמונה** — כל התנועות והמידע נשארים על הלוח.

## מצב חזרה

תפריט `⋯` ← **מצב חזרה**. המערכת יוצרת 20 משתתפי דמה, שכל אחד מהם מקבל פרופיל עומס
משלו ועונה לבד על כל שאלה — כך אפשר להריץ לבד את כל הפעילות מקצה לקצה, כולל
האנימציות, מוני המשיבים, ה־Timeline, גרף 20 המשתתפים וקיר התשובות.

נתוני החזרה יושבים ב־Session נפרד לחלוטין, לעולם אינם נשמרים לדיסק, ואינם מתערבבים
עם הפעילות האמיתית. `⋯` ← **אפס חזרה** מנקה אותם.

## שמירת Session ודוח

בסיום הפעילות (`⋯` ← **סיום פעילות**) ה־Session נשמר כרשומה אנונימית ב־storage
של ה־Durable Object, וכולל: תאריך, מספר משתתפים, מספר משיבים בכל שאלה, דירוגי העומס לאורך כל השלבים,
נקודת השינוי שנבחרה, התשובות הפתוחות, התפלגויות וממוצעים.

מסך `/report` מציג את כל אלה כדוח מעוצב. הכפתור **הורד PDF / הדפס** פותח את
דיאלוג ההדפסה של הדפדפן עם עימוד A4 מוכן — בחרו "Save as PDF". הבחירה בנתיב הזה
במקום יצירת PDF בקוד היא מכוונת: היא היחידה שמעבדת עברית ו־RTL נכון בכל מכשיר.
בנוסף קיים **הורד נתונים (JSON)**.

התשובות הפתוחות מוצגות כלשונן. אין שכתוב, סיכום או "שיפור" שלהן בשום מקום במערכת.

## עריכת התרחיש

כל התוכן — סדר האירועים, נוסח הסטריפים, סוגי המטוסים, השאלות והערות המנחה —
יושב בקובץ אחד: [`shared/scenario.js`](shared/scenario.js). אפשר לערוך אותו בלי לגעת
בשאר המערכת. השרת והלקוח קוראים ממנו את אותו מקור אמת.

סוגי המטוסים (`A320`, `A21N`, `C172`, `P28A`, `UH60`, `F16`) נוספו כדי שהסטריפים
ייראו כמו לוח אמיתי — הם לא הופיעו באפיון, וקל להחליף אותם שם.

## בדיקות

```bash
npm run build
npx wrangler dev --port 3011 --var ADMIN_KEY:testkey &

node tests/engine.test.mjs   # כללי היסוד: נעילה, reconnect, אנונימיות, נעילת תשובה
node tests/flow.test.mjs     # הרצה מלאה של 6 השלבים, החשיפות והדוח
node tests/browser.mjs       # דפדפן אמיתי: כניסה, שאלה, רענון, מסך הקרנה
node tests/admin-phone.mjs   # מסך המנחה במסך טלפון: פריסה, גלילה, יעדי מגע
node tests/admin-access.mjs  # יציאה מהפעילות בלובי, ונעילה אחרי התחלה
node tests/sync.mjs          # קוד מנחה, תצוגת משתתף ב־Admin, הדגשת סטריפ
node tests/reveal-phone.mjs  # כל החשיפות מגיעות למכשיר האישי — ורק אחרי חשיפה
node tests/current-dev.mjs   # כרטיס ההתפתחות הנוכחית, חץ הצפון, סוגי מטוסים
```

הבדיקות רצות מול ה־Worker האמיתי (workerd), לא מול מימוש מדומה.

אפשר להריץ את אותן בדיקות מול ה־deployment החי:

```bash
APP=https://ramon-zero-to-hundred.alon3005nissani.workers.dev \
ADMIN_KEY=<המפתח> node tests/engine.test.mjs
```

`tests/bridge.mjs` מגשר את ה־deployment החי ל־localhost (כולל WebSocket),
לשימוש בסביבות שבהן לדפדפן אין יציאה ישירה לאינטרנט.

## הערה על real-time

ה־Durable Object מחזיק את מצב ה־Session ומשדר לאחר כל שינוי שלוש תצוגות
נפרדות — אחת לכל תפקיד. משתתף מקבל רק את מה שמותר לו לראות, מסך ההקרנה מקבל
מונים ללא תוצאות, והמנחה מקבל את התמונה המלאה. ההפרדה נעשית בשרת, כך שמידע
שאסור להיחשף לא נשלח כלל לדפדפן שאינו אמור לראות אותו.

לקוח ה־WebSocket מתחבר מחדש לבד עם השהיה מדורגת, ומתעורר מיד כשחוזרים
לטאב או כשהרשת חוזרת — מה שחשוב בטלפון שנכנס למצב שינה באמצע הפעילות.
